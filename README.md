# youtube-scout

**정찰병이다. 요약기가 아니다.**

유튜브 링크를 넣으면 자막이 놓친 **화면 정보까지 회수**해 구조화된 보고서를 낸다.
본 것을 등급으로 구분해 보고할 뿐 판단하지 않는다. 도입 여부는 보고를 읽는 사람이 정한다.

다른 요약 도구와 갈리는 지점은 네 가지다.

1. **화면에만 있던 정보** — 발표자가 말하지 않고 띄우기만 한 설정·수치·경로·제약 조건
2. **발표자가 입력한 원문** — 타이핑·붙여넣기한 프롬프트와 명령을 다듬지 않고 그대로
3. **다루지 않은 것** — 말로만 주장하고 시연하지 않은 기능, 넘어간 질문, 편집으로 잘린 구간
4. **이해관계 신호** — 제작자 본인인지, 협찬인지, 제휴 링크인지, 판단 근거가 없는지

## 5분 시작

준비물은 두 가지다 — **Node 20 이상**과 **Gemini API 키**.

```bash
node --version   # v20 이상이면 통과. 없으면 https://nodejs.org 에서 LTS 설치
```

키는 https://aistudio.google.com/apikey 에서 무료로 발급한다 (카드 등록 불요).
발급했으면 아래에서 **자기 환경 하나만** 따라 하면 된다.

### Windows — cmd (명령 프롬프트)

```bat
:: 1) 키 등록 (최초 한 번)
setx GEMINI_API_KEY "발급받은키"

:: 2) 창을 닫고 새 cmd를 연다
::    ⚠️ setx는 지금 열려 있는 창에는 적용되지 않는다 — 여기서 가장 많이 막힌다

:: 3) 실행
npx github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

### Windows — PowerShell

```powershell
# 1) 키 등록 (최초 한 번, 새 창부터 적용)
setx GEMINI_API_KEY "발급받은키"

# 지금 창에서 바로 쓰려면 이것도 함께:
$env:GEMINI_API_KEY="발급받은키"

# 2) 실행 — npx가 아니라 npx.cmd 다
npx.cmd github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

> PowerShell에서 `npx`를 그대로 치면 기본 실행 정책(Restricted)이 `npx.ps1` 로드를 차단해
> `UnauthorizedAccess` 오류가 난다 (실측 2026-07-30). 정책을 바꿀 필요 없이 `.cmd`만 붙이면 된다.

### macOS / Linux

```bash
export GEMINI_API_KEY="발급받은키"   # 영구 설정은 ~/.zshrc 등에 추가
npx github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

### 결과

첫 실행은 npx가 저장소를 내려받느라 수십 초 더 걸린다. 이후에는 캐시로 바로 뜬다.
산출물은 실행한 위치의 `./out/<영상ID>/`에 생긴다 — 구간별 `seg-SSSS-EEEE.md`와
병합본 `_merged.md`. **병합본부터 열면 된다.**

### 배치

```bash
# links.txt — # 주석과 빈 줄을 허용한다
npx github:p7000stars-art/youtube-scout --file links.txt
```

### 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-f, --file <path>` | — | 링크 목록 파일 |
| `-o, --out <dir>` | `./out` | 산출물 디렉터리 |
| `--chunk <sec>` | `480` | 청크 길이. 늘리면 요청 수가 준다 |
| `--models <a,b,c>` | `gemini-3.6-flash` | 쿼터는 모델별로 분리돼 있다 |
| `-y, --yes` | — | 한도 초과 확인 생략 |
| `--harness <path>` | `prompt/meeting-v1.md` | 관찰 규율 교체 (산출물에 각인된다) |

**중단해도 괜찮다.** 다시 실행하면 이미 완료된 구간을 건너뛰고 이어서 처리한다.

## 키 보안

**키는 이 도구 밖으로 나가지 않는다.**

- 중계 서버가 없다. 당신의 컴퓨터에서 Google Generative Language API로 직접 호출한다.
- 이 저장소에 그것을 확인할 수 있는 코드가 전부 들어 있다. 빌드 단계가 없어서
  **읽는 소스가 곧 실행되는 코드다.** 확인할 곳은 `src/extract.js` 한 곳이다.
- 키는 `GEMINI_API_KEY` 환경변수로만 받는다. CLI 인자로는 받지 않는다 —
  인자로 받으면 셸 히스토리와 프로세스 목록에 남는다.
- 키를 로그·산출물·에러 메시지에 출력하지 않는다.

### 키 제한을 걸어 둘 것

발급한 키는 Google Cloud 콘솔에서 제한을 거는 편이 안전하다.

- **API 제한**: Generative Language API 하나만 허용
- **애플리케이션 제한**: 사용 환경에 맞게 설정
- 키가 유출됐다고 판단되면 즉시 폐기하고 새로 발급한다

## 산출물 읽는 법

### 판독 등급 3종

화면에서 옮긴 문자열에는 등급이 붙는다.

| 등급 | 뜻 | 대하는 법 |
|---|---|---|
| `확실` | 글자 단위로 또렷하게 읽혔다 | 그래도 긴 문자열이면 교차검증 |
| `추정` | 문맥상 그렇게 보이지만 흐리거나 잘렸다 | 그대로 쓰지 말 것 |
| `불가` | 읽을 수 없었다 | 영상을 직접 확인해야 하는 지점 |

등급은 정확성의 **자기 신고**다. 이 도구는 날조를 막는 대신 날조 위험 구간을 드러내게 만든다.
자세한 근거는 [docs/harness-design.md](docs/harness-design.md).

### 미검증 배너

모든 병합본 첫머리에 붙는다.

> ⚠️ Gemini 추출 원본. **미검증** 상태다.

특히 **명령어·URL·저장소 경로·ID·해시**는 실제로 날조된 실적이 있다. 실측에서 실재하지 않는
저장소 경로를 만들어 냈고 명령어 플래그의 대소문자를 틀렸다. 뼈대는 맞고 세부에서 무너진다.

> 영상은 **무엇을 봐야 하는지**를 알려준다. 정확한 문자열은 **공식 소스**에서 가져와라.

### ⛔ 표시

```
> ⛔ 이 구간은 추출에 실패했습니다. 내용이 통째로 비어 있습니다.
```

병합본 안에 이 표시가 있으면 그 구간은 통째로 비어 있다는 뜻이다. 누락은 침묵하지 않는다.
같은 명령을 다시 실행하면 그 구간만 재시도한다.

### frontmatter

```yaml
model: gemini-3.6-flash
media_resolution: MEDIA_RESOLUTION_HIGH
harness: meeting-v1          # 어떤 관찰 규율로 뽑았는지의 각인
chunks: 7/8                  # 성공/전체 — 8개 중 1개가 ⛔다
status: unverified
```

## 429 / 403 대처

| 증상 | 정체 | 대처 |
|---|---|---|
| `429 RPD` | 모델의 **일일** 한도 소진 | **기다려도 안 풀린다.** 다른 모델을 `--models`에 추가하거나 내일 재실행 (완료 구간은 건너뛴다) |
| `429 TPM/RPM` | 순간 한도 | 도구가 자동으로 대기 후 재시도한다 (최대 3회, 상한 90초) |
| `403` | 재생 불가 (회원 전용·비공개·삭제) | 처리 대상이 아니다. 사전 차단을 통과했는데 발생했다면 유튜브 페이지 구조 변경 가능성 |

**429는 두 종류이고 대응이 정반대다.** 이 도구는 응답 본문의 `quotaId`를 읽어 둘을 구분하고
서로 다른 문구로 안내한다. "잠시 후 재시도"로 뭉개지 않는다.

무료 등급의 실제 일일 할당은 문서 값과 다를 수 있다. 실측에서는 모델당 20회였다.
그래서 이 도구는 **투입 전에 예상 요청 수를 보여주고**, 한도를 넘을 것 같으면 대안 세 가지를
제시한 뒤 확인을 받는다 — 청크 확대 / 분할 실행 / 모델 추가.

## 하네스

이 도구의 정수는 코드가 아니라 **관찰 규율**이다.

- [`prompt/meeting-v1.md`](prompt/meeting-v1.md) — 규율 전문
- [`docs/harness-design.md`](docs/harness-design.md) — 각 장치가 왜 거기 있는지

하네스는 코드에 하드코딩되어 있지 않다. 파일에서 읽어 `systemInstruction`으로 주입하므로
누구나 읽고 검증할 수 있고, `--harness`로 교체할 수도 있다.

다만 **교체는 산출물에 각인된다.** frontmatter의 `harness:` 값이 바뀐다. 규율을 바꿔서 만든
보고서와 원본 규율로 만든 보고서는 신뢰 성격이 다른 문서이므로, 나중에 구별할 수 있어야 한다.

## 경계

- **공개 영상만 처리한다.** 회원 전용·비공개 영상은 우회하지 않는다. 기능이 없는 정도가 아니라
  코드로 사전 차단한다 (`src/meta.js`). Gemini에는 로그인 세션이 없어 애초에 접근하지 못하고,
  우회할 방법을 추가할 계획도 없다.
- **공개 메타데이터만 읽는다.** watch 페이지의 공개 정보를 읽을 뿐 영상 스트림에 직접 접근하거나
  보호 장치를 우회하지 않는다. 영상 자체는 Gemini가 공개 URL로 처리한다.
- **산출물은 개인 학습·검토 목적이다.** 추출본을 그대로 재배포하는 것은 권장하지 않는다.
  원 저작물의 내용이 담긴 문서다.
- **요약·판단·추천 기능은 없다.** 앞으로도 넣지 않는다. 판단은 읽는 사람이 한다.

## 개발

```bash
node --test                  # 테스트
node scripts/check-leak.js   # 커밋 전 유출 검사
```

런타임 의존성이 없다. Node 20+ 내장 기능(`fetch`, `node:util` parseArgs, `node:test`)만 쓴다.
TypeScript를 쓰지 않고 JSDoc + `// @ts-check`로 타입을 표기하는 것도 같은 이유다 —
빌드 단계가 없어야 **읽는 소스가 곧 실행되는 코드**가 되고, 그것이 키를 다루는 도구의
검증 가능성을 지탱한다.
