# youtube-scout

**정찰병이다. 요약기가 아니다.**

유튜브 링크를 넣으면 자막이 놓친 **화면 정보까지 회수**해 구조화된 보고서를 낸다.
본 것을 등급으로 구분해 보고할 뿐 판단하지 않는다. 도입 여부는 보고를 읽는 사람이 정한다.

다른 요약 도구와 갈리는 지점은 네 가지다.

1. **화면에만 있던 정보** — 발표자가 말하지 않고 띄우기만 한 설정·수치·경로·제약 조건
2. **발표자가 입력한 원문** — 타이핑·붙여넣기한 프롬프트와 명령을 다듬지 않고 그대로
3. **다루지 않은 것** — 말로만 주장하고 시연하지 않은 기능, 넘어간 질문, 편집으로 잘린 구간
4. **이해관계 신호** — 제작자 본인인지, 협찬인지, 제휴 링크인지, 판단 근거가 없는지

---

## 제작 사유

기술 영상은 도구 도입을 판단하는 재료다. 그런데 자막 기반 요약은 판단에 필요한 것을 정확히
버린다 — 발표자가 말하지 않고 화면에 띄우기만 한 설정과 수치, 타이핑한 프롬프트의 원문,
그리고 "보여주지 않은 것". 말로 요약되는 부분은 대개 이미 아는 이야기고, 판단이 갈리는 정보는
화면과 침묵에 있다.

그래서 요약기가 아니라 정찰병을 만들었다. 영상을 보지 않은 사람이 도입 여부를 판단할 수 있도록,
본 것을 등급으로 구분해 보고하고 판단은 하지 않는 도구다. 보고서는 마크다운으로 남아 회의
재료나 지식 베이스의 원료가 된다 — 이 도구는 수집까지만 하고, 그다음은 사람의 몫이다.

---

## 어떻게 동작하나

링크 하나가 보고서가 되기까지:

1. **사전 정찰** — watch 페이지에서 길이와 재생 가능 여부를 확인한다. 회원 전용이면 API를
   한 번도 부르지 않고 사유와 함께 건너뛴다
2. **작전 계획** — 영상을 480초 청크로 나누고 예상 요청 수를 계산해 먼저 보여준다.
   무료 쿼터는 생각보다 작다 (실측: 문서상 1,500회, 실제 20회)
3. **추출** — 각 청크를 Gemini에 고해상도(HIGH) 고정으로 보낸다. 저해상도는 작은 글자를
   날조하면서 날조 사실조차 신고하지 않았다 (실측). 관찰 규율은 코드가 아니라 하네스 파일로
   주입된다
4. **생존 운전** — 429의 정체를 응답 본문에서 판별해(일일 소진 vs 순간 한도) 대응을 가르고,
   죽은 모델은 즉시 교체하며, 실패 이력은 파일에 남아 다음 실행이 같은 벽을 다시 들이받지
   않는다
5. **보고** — 구간 파일을 계획 기반으로 병합한다. 누락은 ⛔로 표시되고 침묵하지 않는다.
   산출물에는 모델·해상도·규율 해시·버전이 각인된다

기술 선택은 전부 한 가지 기준을 따른다 — **검증 가능성**.

| 선택 | 이유 |
|---|---|
| 런타임 의존성 0, 빌드 없음 | 읽는 소스 = 실행되는 코드. 키를 다루는 도구의 신뢰 근거 |
| 서버 없음 | 키가 사용자 컴퓨터 밖으로 나갈 경로 자체가 없다 |
| 하네스 외부 파일 | 규율을 누구나 읽고, 바꾸면 산출물에 각인된다 |
| 상태는 전부 보이는 파일 | 구간·상태·로그 — 숨은 상태가 없어 어디서든 재개된다 |

설계 결정의 근거는 대부분 실측이다: [docs/design-story.md](docs/design-story.md)

## 5분 시작

준비물은 두 가지다 — **Node 20 이상**과 **Gemini API 키**.

```bash
node --version   # v20 이상이면 통과. 없으면 https://nodejs.org 에서 LTS 설치
```

키는 https://aistudio.google.com/apikey 에서 무료로 발급한다 (카드 등록 불요).

여기서 길이 갈린다. **계속 쓸 거라면 `init`**, 한 번만 볼 거라면 **직접 실행**이다.

## 방법 1: `init` — 더블클릭 실행 환경 (권장)

링크를 파일에 모아 두고 실행 파일을 더블클릭하는 방식이다. 매번 터미널에 경로와 옵션을
치지 않아도 된다.

```bash
npx github:p7000stars-art/youtube-scout init
```

현재 폴더에 `youtube-scout-run/`이 생긴다.

```
youtube-scout-run/
├─ run.bat      ← Windows: 더블클릭
├─ run.sh       ← macOS/Linux: ./run.sh  (처음 한 번 chmod +x run.sh)
└─ links.txt    ← 여기에 링크를 한 줄에 하나씩
```

1. `links.txt`를 열어 링크를 붙여넣는다 (`#` 주석과 빈 줄은 무시된다)
2. 키를 등록한다 — `links.txt` 상단에 OS별 안내가 들어 있다
3. Windows는 `run.bat` 더블클릭, macOS/Linux는 `./run.sh`

산출물은 `youtube-scout-run/out/`에 생긴다. 폴더째 옮겨도 그대로 동작한다.

**키를 먼저 등록하고 `init`을 실행하면** 그 시점에 실제로 쓸 수 있는 모델을 조회해
`MODELS` 목록에 채워 준다. 키가 없으면 기본 모델 하나로 넣는다.

**`init`은 몇 번 실행해도 안전하다.** 이미 있는 파일은 건드리지 않는다 — `links.txt`의
링크와 `run` 파일에서 바꿔 둔 모델 순서가 보존된다. 모델 목록을 새로 받고 싶으면
해당 `run` 파일을 지우고 `init`을 다시 실행한다.

청크·모델을 바꾸려면 `run.bat` / `run.sh` 맨 위 `CHUNK`, `MODELS` 값을 고친다.
Windows에서 더블클릭은 cmd로 실행되므로 PowerShell 실행 정책 문제도 자동으로 비켜 간다.

> `run.bat`은 안내문이 전부 영어다. `.bat`의 한글은 콘솔 코드페이지 문제로 깨져서
> (실측 2026-07-30) 의도적으로 넣지 않았다. 한국어 안내는 `links.txt`에 있다.

## 방법 2: 직접 실행 (단건·일회성)

아래에서 **자기 환경 하나만** 따라 하면 된다.

### Windows — cmd (명령 프롬프트)

```bat
:: 1) 키 등록 (최초 한 번)
setx GEMINI_API_KEY "발급받은키"

:: 2) 창을 닫고 새 cmd를 연다
::    ⚠️ setx는 지금 열려 있는 창에는 적용되지 않는다 — 여기서 가장 많이 막힌다

:: 3) 실행
npx github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

### Windows — PowerShell

```powershell
# 1) 키 등록 (최초 한 번, 새 창부터 적용)
setx GEMINI_API_KEY "발급받은키"

# 지금 창에서 바로 쓰려면 이것도 함께:
$env:GEMINI_API_KEY="발급받은키"

# 2) 실행 — npx가 아니라 npx.cmd 다
npx.cmd github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

> PowerShell에서 `npx`를 그대로 치면 기본 실행 정책(Restricted)이 `npx.ps1` 로드를 차단해
> `UnauthorizedAccess` 오류가 난다 (실측 2026-07-30). 정책을 바꿀 필요 없이 `.cmd`만 붙이면 된다.

### macOS / Linux

```bash
export GEMINI_API_KEY="발급받은키"   # 영구 설정은 ~/.zshrc 등에 추가
npx github:p7000stars-art/youtube-scout "https://www.youtube.com/watch?v=..."
```

### 결과

첫 실행은 npx가 저장소를 내려받느라 수십 초 더 걸린다. 이후에는 캐시로 바로 뜬다.
산출물은 실행한 위치의 `./out/` 아래에 영상별 폴더로 생긴다.

```
out/
├─ 클로드 디자인 2.0 완전히 달라졌습니다 (4단계 총정리)_c-ny7pegVHI/
│  ├─ 보고서.md         ← 열어야 할 파일. 전 구간을 합친 최종본
│  └─ parts/            ← 구간별 원본. 보통 볼 일이 없다
│     ├─ seg-0000-0480.md
│     └─ seg-0475-0955.md
└─ _batch.log           ← 실행 로그
```

**`보고서.md`부터 열면 된다.** 폴더 안에 파일이 하나뿐이라 헷갈릴 여지가 없다 —
구간별 원본은 `parts/`로 내려두었다.

폴더명 끝의 `_c-ny7pegVHI`는 영상 ID다. 지우지 말 것 — 이 도구가 "이 영상은 어디까지
했는지"를 이 ID로 찾는다. 제목은 유튜버가 바꿀 수 있어서 재개의 기준이 될 수 없다.

> **이전 버전을 쓰던 경우:** 예전 폴더(`c-ny7pegVHI/`처럼 ID만 있는 이름)도 그대로
> 인식된다. 재실행하면 새 폴더를 만들지 않고 그 폴더에서 이어서 처리하며, 기존
> `_merged.md`는 건드리지 않는다. 새 산출물부터 위 구조가 적용된다.

### 배치

```bash
# links.txt — # 주석과 빈 줄을 허용한다
npx github:p7000stars-art/youtube-scout --file links.txt
```

### 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-f, --file <path>` | — | 링크 목록 파일 |
| `-o, --out <dir>` | `./out` | 산출물 디렉터리 |
| `--chunk <sec>` | `480` | 청크 길이. 늘리면 요청 수가 준다 |
| `--models <a,b,c>` | `gemini-3.6-flash` | 쿼터는 모델별로 분리돼 있다 |
| `-y, --yes` | — | 한도 초과 확인 생략 |
| `--harness <path>` | `prompt/meeting-v1.md` | 관찰 규율 교체 (산출물에 각인된다) |

**중단해도 괜찮다.** 다시 실행하면 이미 완료된 구간을 건너뛰고 이어서 처리한다.

> **업데이트가 반영되지 않는 것 같을 때** — `npx github:...`는 받은 판을 캐시에
> 재사용할 수 있다. 최신 수정이 안 보이면 cmd에서 캐시를 비우고 다시 실행한다:
>
> ```
> rmdir /s /q "%LocalAppData%\npm-cache\_npx"
> ```
>
> (macOS/Linux: `rm -rf ~/.npm/_npx`)

## 모델 목록은 자동으로 대조된다

실행할 때마다 한 번, 지금 쓸 수 있는 모델 목록을 조회해 지정한 목록과 맞춰 본다.
이 조회는 추출 쿼터를 쓰지 않으므로 예산이 깎이지 않는다.

```
! gemini-2.5-flash 은(는) 더 이상 제공되지 않아 제외합니다
i 새 모델 3종을 순환 꼬리에 편입 (검증 풀 소진 시에만 사용): a-flash, b-flash, c-flash
```

- **사라진 모델**은 경고와 함께 제외된다. 없는 모델로 첫 청크에서 404를 맞고
  자기 키나 링크를 의심하는 상황을 막는다.
- **목록에 있어도 죽은 모델이 있다.** 조회 목록에 남아 있는데 실제 호출은 404를
  돌려주는 퇴역 모델이 실측됐다 (2026-07-30, `gemini-2.5-flash`). 이런 모델은
  실행 중 발견 즉시 제외하고 다음 모델로 넘어간다 — 404는 쿼터를 쓰지 않으므로
  헛손질 1회로 끝난다.
- **새 모델**은 목록 **맨 뒤**에 붙는다. 앞에 두지 않는 이유가 있다 — 새 모델은
  작은 글자 판독력이 검증되지 않았고, **나쁜 모델은 티가 나지 않는다.** 못 읽었다고
  신고하는 대신 그럴듯하게 채우고 "판독불가 없음"이라 선언한 실측이 있다.
  게다가 신형·프리뷰 모델일수록 쿼터가 더 조여 있다.
  꼬리에 있으면 앞쪽 모델이 일일 한도로 소진됐을 때만 쓰인다.
  써 보고 좋았으면 `run` 파일이나 `--models`에서 직접 앞으로 옮긴다 — 그 수동 승격이
  검증 게이트다.
- **조회가 실패하면** 아무 말 없이 지정한 목록 그대로 진행한다. 대조는 보조 기능이라
  이것 때문에 추출이 막히지 않는다.

### 실패한 모델은 `model-status.txt`에 쌓인다

실행 폴더(`links.txt` 옆)에 `model-status.txt`가 생긴다. 지난 실행에서 어떤 모델이
어떻게 실패했는지를 적어 두는 파일이고, 도구가 자동으로 기록한다.

```
# 형식: <모델> <demoted|blocked> <사유> x<횟수> <YYYY-MM-DD> [# 메모]
gemini-2.5-flash        blocked  404      x3  2026-07-30
gemini-2.0-flash-lite   demoted  tpm-480  x1  2026-07-30  # 480초에서 분당 한도 초과
gemini-3.6-flash        demoted  rpd      x1  2026-07-30
```

- `demoted` — 제외는 아니다. 모델 순환의 **맨 뒤로** 미룬다. 앞쪽 모델이 다 소진되면 여전히 쓰인다.
- `blocked` — 이번부터 아예 제외한다. 실행 시작에 이유와 함께 알려 준다.
- 사유 `404`는 퇴역 추정, `rpd`는 일일 한도 소진, `tpm-480`은 **480초짜리 요청에서** 분당 한도를 넘었다는 뜻이다.
  숫자는 설정값(`--chunk`)이 아니라 **실제로 막힌 구간의 길이**다 — 마지막 구간은 영상 끝에서 잘려 더 짧으므로
  `tpm-289` 같은 기록도 나온다.
- **줄을 지우면 그 모델이 복권된다.** 메모장으로 지우고 저장하면 끝이다. 숨은 상태가 없다.
- 상태를 `blocked`로 직접 고쳐 강제 차단해도 된다. 도구가 되돌리지 않는다.
- **`--models`와 `run` 파일은 도구가 절대 고치지 않는다.** 그 순서는 당신의 검증 게이트다.
  상태는 별도 파일에만 쌓인다.

몇 가지 판정 규칙:

- `rpd`는 **날짜가 바뀌면 저절로 사라진다.** 일일 한도는 결함이 아니라 오늘의 잔량 문제다.
  그래서 `rpd`는 몇 번을 쌓여도 `blocked`가 되지 않는다 — 많이 쓴 모델을 차단하는 것은 정반대의 결과다.
  (같은 날 재실행에서는 뒤로 미루는 것이 실제로 이득이다)
- `tpm-480` 기록은 `--chunk 240`으로 줄여 실행하면 **무효 처리된다.** 요청이 절반이면 통과할 수 있으므로,
  그 판정은 480초 청크에만 해당한다.
- `404`와 `tpm-<초>`는 같은 조건에서 **3번** 관찰되면 `blocked`로 올라간다.

**왜 한 번에 영구 제외하지 않는가.** 즉시 확정하면 오판을 스스로 고칠 수 없다. 진짜 일시
혼잡이 구조적 한도처럼 보이는 경우, 서버가 잠깐 404를 주는 경우가 실제로 있다. 재확인
비용은 거의 없다 — 404는 쿼터를 쓰지 않고 1초 만에 끝난다. 그 싼 관찰을 두 번 더 하는
대가로 오판을 되돌릴 여지를 산다. 이 도구가 화면 글자를 `확실`/`추정`/`불가`로 나눠
보고하는 것과 같은 철학이다: **한 번 본 것은 추정이고, 세 번 본 것이 확실이다.**

기록은 발생 즉시 파일에 쓰인다. 중간에 창을 닫아도 그때까지의 관찰은 남는다.

---

## 키 보안

**키는 이 도구 밖으로 나가지 않는다.**

- 중계 서버가 없다. 당신의 컴퓨터에서 Google Generative Language API로 직접 호출한다.
- 이 저장소에 그것을 확인할 수 있는 코드가 전부 들어 있다. 빌드 단계가 없어서
  **읽는 소스가 곧 실행되는 코드다.** 확인할 곳은 `src/extract.js` 한 곳이다.
- 키는 `GEMINI_API_KEY` 환경변수로만 받는다. CLI 인자로는 받지 않는다 —
  인자로 받으면 셸 히스토리와 프로세스 목록에 남는다.
- 키를 로그·산출물·에러 메시지에 출력하지 않는다.

### 키 제한을 걸어 둘 것

발급한 키는 Google Cloud 콘솔에서 제한을 거는 편이 안전하다.

- **API 제한**: Generative Language API 하나만 허용
- **애플리케이션 제한**: 사용 환경에 맞게 설정
- 키가 유출됐다고 판단되면 즉시 폐기하고 새로 발급한다

## 산출물 읽는 법

### 판독 등급 3종

화면에서 옮긴 문자열에는 등급이 붙는다.

| 등급 | 뜻 | 대하는 법 |
|---|---|---|
| `확실` | 글자 단위로 또렷하게 읽혔다 | 그래도 긴 문자열이면 교차검증 |
| `추정` | 문맥상 그렇게 보이지만 흐리거나 잘렸다 | 그대로 쓰지 말 것 |
| `불가` | 읽을 수 없었다 | 영상을 직접 확인해야 하는 지점 |

등급은 정확성의 **자기 신고**다. 이 도구는 날조를 막는 대신 날조 위험 구간을 드러내게 만든다.
자세한 근거는 [docs/harness-design.md](docs/harness-design.md).

### 미검증 배너

모든 병합본 첫머리에 붙는다.

> ⚠️ Gemini 추출 원본. **미검증** 상태다.

특히 **명령어·URL·저장소 경로·ID·해시**는 실제로 날조된 실적이 있다. 실측에서 실재하지 않는
저장소 경로를 만들어 냈고 명령어 플래그의 대소문자를 틀렸다. 뼈대는 맞고 세부에서 무너진다.

> 영상은 **무엇을 봐야 하는지**를 알려준다. 정확한 문자열은 **공식 소스**에서 가져와라.

### ⛔ 표시

```
> ⛔ 이 구간은 추출에 실패했습니다. 내용이 통째로 비어 있습니다.
```

병합본 안에 이 표시가 있으면 그 구간은 통째로 비어 있다는 뜻이다. 누락은 침묵하지 않는다.
같은 명령을 다시 실행하면 그 구간만 재시도한다.

### frontmatter

```yaml
model: gemini-3.6-flash
media_resolution: MEDIA_RESOLUTION_HIGH
harness: meeting-v1          # 어떤 관찰 규율로 뽑았는지의 각인 (이름)
chunks: 7/8                  # 성공/전체 — 8개 중 1개가 ⛔다
status: unverified
harness_sha256: 9b58a710ac3b # 하네스 내용의 해시 — 이름이 같아도 수정본은 여기서 갈린다
scout_version: 0.2.0         # 이 산출물을 뽑은 도구 버전
temperature: 0.1
```

무료 등급은 모델을 순환해 쓰기 때문에 **같은 영상을 다시 돌려도 결과가 달라진다.**
위 다섯 줄(`model`·`harness_sha256`·`scout_version`·`temperature`·`media_resolution`)이
그때 무엇이 달랐는지 되짚을 근거다. 결과가 이상하면 이전 산출물의 이 값들과 비교해 보면 된다.

## 429 / 404 / 403 대처

| 증상 | 정체 | 대처 |
|---|---|---|
| `429 RPD` | 모델의 **일일** 한도 소진 | **기다려도 안 풀린다.** 도구가 즉시 다음 모델로 교체한다. 전 모델 소진 시 내일 재실행 (완료 구간은 건너뛴다) |
| `429 TPM/RPM` | 순간 한도 | 도구가 자동으로 대기 후 재시도한다 (최대 3회, 상한 90초) |
| `404` | **퇴역 모델** (목록에는 있으나 실사용 불가) | 도구가 즉시 다음 모델로 교체한다. 요약에 표시되면 `run` 파일·`--models`에서 그 모델을 제거하라 — **내일도 안 된다** |
| `403` | 재생 불가 (회원 전용·비공개·삭제) | 처리 대상이 아니다. 사전 차단을 통과했는데 발생했다면 유튜브 페이지 구조 변경 가능성 |

**429는 두 종류이고 대응이 정반대다.** 이 도구는 응답 본문의 `quotaId`를 읽어 둘을 구분하고
서로 다른 문구로 안내한다. "잠시 후 재시도"로 뭉개지 않는다.
요약에서도 **일일 소진(내일 회복)과 퇴역(영구)을 갈라서** 알려준다.

무료 등급의 실제 일일 할당은 문서 값과 다를 수 있다. 실측에서는 모델당 20회였다.
그래서 이 도구는 **투입 전에 예상 요청 수를 보여주고**, 한도를 넘을 것 같으면 대안 세 가지를
제시한 뒤 확인을 받는다 — 청크 확대 / 분할 실행 / 모델 추가.

## 하네스

이 도구의 정수는 코드가 아니라 **관찰 규율**이다.

- [`prompt/meeting-v1.md`](prompt/meeting-v1.md) — 규율 전문
- [`docs/harness-design.md`](docs/harness-design.md) — 각 장치가 왜 거기 있는지

하네스는 코드에 하드코딩되어 있지 않다. 파일에서 읽어 `systemInstruction`으로 주입하므로
누구나 읽고 검증할 수 있고, `--harness`로 교체할 수도 있다.

산출물에는 하네스 **내용의 해시**가 각인된다(`harness_sha256`) — 파일을 수정하면 이름이
같아도 구분된다. 이름만으로 각인하면 규율을 고쳐 놓고 이름을 그대로 둔 산출물을 원본과
구별할 방법이 없기 때문이다.

다만 **교체는 산출물에 각인된다.** frontmatter의 `harness:` 값이 바뀐다. 규율을 바꿔서 만든
보고서와 원본 규율로 만든 보고서는 신뢰 성격이 다른 문서이므로, 나중에 구별할 수 있어야 한다.

## 경계

- **공개 영상만 처리한다.** 회원 전용·비공개 영상은 우회하지 않는다. 기능이 없는 정도가 아니라
  코드로 사전 차단한다 (`src/meta.js`). Gemini에는 로그인 세션이 없어 애초에 접근하지 못하고,
  우회할 방법을 추가할 계획도 없다.
- **공개 메타데이터만 읽는다.** watch 페이지의 공개 정보를 읽을 뿐 영상 스트림에 직접 접근하거나
  보호 장치를 우회하지 않는다. 영상 자체는 Gemini가 공개 URL로 처리한다.
- **산출물은 개인 학습·검토 목적이다.** 추출본을 그대로 재배포하는 것은 권장하지 않는다.
  원 저작물의 내용이 담긴 문서다.
- **요약·판단·추천 기능은 없다.** 앞으로도 넣지 않는다. 판단은 읽는 사람이 한다.

## 이 도구는 끝이 아니라 첫 칸이다

산출물은 답이 아니라 재료다. 보고서가 나온 뒤의 일은 이 도구 밖에서, 사람이 한다.

```
영상 → [youtube-scout] → 미검증 보고서
                              ↓
                      검토 · 질문 (사람, 또는 사람이 쓰는 AI)
                              ↓
                      공식 소스와 교차검증  ← 미검증 배너가 가리키는 그 단계
                              ↓
                      각자의 지식 베이스로
```

이 경계는 기능이 모자라서 생긴 것이 아니라 설계다. 수집하는 도구가 판단까지 하면 판단의 오류가
사실처럼 다음 단계로 흘러간다. 등급과 출처가 붙은 관찰은 틀렸을 때 어디가 틀렸는지 짚을 수
있지만, 판단으로 압축된 문장은 그 흔적을 지운다. 그래서 이 도구는 관찰을 넘기는 데서 멈춘다.

넘겨받은 쪽이 할 일은 정해져 있다. `추정`·`불가`로 표시된 항목을 공식 소스에서 확인하고,
긴 고유 문자열(명령어·URL·경로·ID)은 영상이 아니라 공식 문서에서 가져온다. 영상은 **무엇을
봐야 하는지**를 알려 주고, 정확한 값은 공식 소스가 준다 — 역할이 다르다.

frontmatter의 `status: unverified`를 지우는 것은 이 도구가 아니라 당신의 검증이다.

## 개발

```bash
node --test                  # 테스트
node scripts/check-leak.js   # 커밋 전 유출 검사
```

런타임 의존성이 없다. Node 20+ 내장 기능(`fetch`, `node:util` parseArgs, `node:test`)만 쓴다.
TypeScript를 쓰지 않고 JSDoc + `// @ts-check`로 타입을 표기하는 것도 같은 이유다 —
빌드 단계가 없어야 **읽는 소스가 곧 실행되는 코드**가 되고, 그것이 키를 다루는 도구의
검증 가능성을 지탱한다.
